# 01.08 Recap: Five Takeaways (about 2 min)

Source: Developer Module 1, screen 8 of 9.

1. **Tokens are the unit of input, output and cost.** Think and budget in tokens, since that is what the API meters and the context window measures.
2. **The context window is a fixed token budget** holding the whole request at once. Oversized input errors before generation; hitting the ceiling mid-generation returns truncated output with the stop reason `model_context_window_exceeded`. Managing history is the application's job.
3. **Sampling makes generation non-deterministic.** The same prompt can return different wording each run, so testing on exact text is unreliable. This is what evals are for.
4. **Model choice and reasoning mode are separate, composable levers.** Use the smallest model and simplest reasoning and prompting that meet your eval; add capability only where the eval says you need it.
5. **A developer reaches Claude over a REST API, usually through an SDK.** Pick synchronous, streaming, async/await or batch depending on whether a user is waiting and whether the work is real-time or bulk offline.
