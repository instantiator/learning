# 01.03 Models & Reasoning (about 10 min)

Source: Developer Module 1, screen 3 of 9. Three tabs: The Model Family, Reasoning Modes, How They Work Together.

## The Claude model family
- Four tiers, each a different trade-off of cost, latency and capability:
  - **Haiku:** fast and cheap, for tasks that fit within its capability.
  - **Sonnet:** the balanced default for most production work.
  - **Opus:** for demanding work beyond what Sonnet handles.
  - **Fable:** the most capable tier, for the hardest reasoning, coding and agentic work.
- Rule of thumb: start on Sonnet. Move up only when an eval shows Sonnet missing your quality bar. Move down to Haiku only when an eval shows the quality drop is acceptable.
- The lineup and model IDs change, so confirm them in the platform docs when you build.

## Reasoning modes are a separate setting
- Which model to run and whether it reasons before answering are two separate decisions, and reasoning is chosen per call.
- On current models the mode is adaptive thinking: the model decides when and how much to think. You tune depth with an effort setting, not a fixed token budget.
- The older `budget_tokens` control is deprecated, and on the newest generations it returns a 400 error.
- On the newest models thinking content is omitted from responses by default. Ask for summarised display if you want to show it.
- Reasoning pays off on hard, multi-step problems and is wasted on lookups and classification.
- Defaults differ by model (some think adaptively by default or always), so check yours.

## How the two combine
- The two settings are independent:
  - capable model, reasoning off: fast and direct;
  - smaller model, reasoning on: spends more tokens thinking;
  - hardest tasks: capable model with a higher effort setting.
- Where it is covered later: Module 2 teaches enabling reasoning and handling thinking blocks; Module 4 covers choosing a model by cost, latency and quality.
