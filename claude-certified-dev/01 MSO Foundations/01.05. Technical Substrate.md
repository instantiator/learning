# 01.05 Technical Substrate (about 12 min)

## SDK vs raw REST
- Claude is reached over an HTTP REST API: send a request to an endpoint with your API key and a JSON body, read a JSON response.
- You can call it with any HTTP client, but usually you use an official SDK (Python, TypeScript and others).
- The SDK is a thin convenience layer over the same API. It handles authentication, building requests, retries and parsing responses, so you write less boilerplate.
- Same API, same model either way. Module 2 builds on the SDK and the Messages API.

## Sync, streaming and real-time
- **Synchronous:** send a request and wait for the whole response in one piece. Fine for short responses and backend jobs where nobody is waiting.
- **Streaming:** for long responses or when a user is watching, the response arrives in pieces as it is generated, so output appears immediately and your code reassembles the final message.
- Streaming uses server-sent events over the same HTTP connection.
- Module 2 covers consuming a stream safely and recovering when it is interrupted.

## Async for high-volume work
Two patterns, solving different problems:
- **Async client (concurrency):**
  - Python SDK: the `AsyncAnthropic` client uses non-blocking async/await.
  - TypeScript SDK: the normal client is already Promise-based, so there is no separate async class.
  - Calls still return in real time, but your app can do other work while waiting.
- **Message Batches API (bulk, offline):**
  - Submit a large set of requests in one call, get an identifier back, then poll for completion.
  - Jobs can take up to 24 hours but cost less per token.
  - Suits offline pipelines, eval runs and bulk jobs where cost matters more than turnaround time.
