# 01.02 How LLMs Behave (about 12 min)

Source: Developer Module 1, screen 2 of 9. Four tabs: Tokens, Context Window, Sampling, Non-determinism.

## Tokens: the unit of input, output and cost
- Claude reads tokens, not characters or words. How many characters make a token depends on the model's tokenizer and changes between model generations, so treat any chars-per-token rule of thumb as approximate and recheck it when you build.
- Everything is counted in tokens: prompt, conversation history, tool definitions, tool results, and the generated response.
- Tokens are both the billing unit and the budget unit. Estimate cost and "will it fit?" in tokens, not words.

## Context window: a fixed budget
- The context window is the total tokens the model can handle in one request. It has to hold the system prompt, the whole conversation so far, injected documents, tool results, and the model's output.
- Two edge behaviours:
  - Input already larger than the window: rejected with a validation error before generation starts.
  - Input fits but generation hits the ceiling: current models stop and return what they have, with the stop reason `model_context_window_exceeded`, instead of raising an error.
- Long sessions need the application to trim or summarise history before each call.
- Trap: in development inputs are short so the window rarely fills; in production longer inputs and more turns fill it quickly. Module 2 returns to this failure.

## Sampling: why the same prompt can differ
- At each step the model produces a probability distribution over next tokens and samples from it.
- Temperature reshapes that distribution: lower is more repeatable, higher is more varied.
- Because it is sampled, two runs can differ in wording even when both are correct.
- Model-dependent: the newest Claude models do not accept non-default sampling parameters. Setting `temperature`, `top_p` or `top_k` gives a 400 error, and you steer behaviour through prompting instead.
- Even where temperature is accepted, temperature 0 gives more repeatable output but not guaranteed identical output. Check the API reference for current support.

## Non-determinism: what it means for testing
- Identical inputs do not guarantee identical outputs.
- Do not assert on exact response text. Assert on properties that must hold: a field is present, a value is in range, the output parses.
- To judge meaning rather than structure, use an eval with a model-graded judge.
- This is why the course treats evals as the standard for correctness; Module 3 builds that skill.
