# 02.14 Context Engineering: Watch Out (about 5 min)

Source: Developer Module 2, screen 14 of 29. Title: "The session that ran fine in development, then hit a ceiling in production".

## The trap
Tool outputs consume context just like prompts and file reads. The window is a fixed budget for the system prompt, history, and every tool call and result so far. Short outputs make it last; larger outputs run it down faster. The window didn't change, what each turn spends did. A session that handles twenty turns in development can fail at turn eight in production.

## Postmortem (composite)
- A receipts-processing agent ran under a **40k-token budget that the team chose** as a cost control. This was not the model's limit: current API models carry at least 200k tokens, and the newest flagship tier serves 1M by default.
- Development: twenty test receipts, each tool result about 800 tokens; a full twenty-turn session used about 18,000 tokens, well under budget.
- Production: receipts came with supporting documents, transaction records and correspondence, so tool output averaged about 3,200 tokens. Eight turns of tool output alone were about 25,600 tokens; with system prompt, user and assistant messages the running total hit the 40k cap at turn eight, before the analysis finished.
- It looked like degraded tool selection (wrong tools, incomplete analyses). The real cause: accumulated, never-pruned tool outputs had crowded out the system prompt and early instructions, so the agent was deciding without its original guidance.
- Found by a token-usage audit two days after deployment. Fix: prune tool outputs after use and compact proactively before reaching the cap.

| | Development | Production |
|---|---|---|
| Model window | 200k standard, 1M on current top tiers | same |
| Team budget cap | 40k | 40k |
| Avg tool output | about 800 tokens | about 3,200 tokens |
| Window state | sessions complete without reaching the cap | cap reached at turn 8 |
| Symptom | none | wrong tool picks and incomplete output from turn 8 |
| Cause found by | n/a | token audit |

## Takeaways
- Test fixtures are nearly always smaller than production data. Measure the token cost of a tool result against the largest input you can find in your target data before shipping.
- Context overflow is often misread as a tool-selection failure. If tool choice degrades after a fixed number of turns, check whether the window is filling before you debug the schema (cf. 02.08).
