## The task
A partial agent implementation has two gaps to fill:
1. the **description** for the `update_record` tool;
2. the **HITL checkpoint code** before `update_record` executes.

## The partial implementation (described, not copied)
- Two tools. `read_record` has the description "Use this to read a customer record by customer_id" and a `customer_id` string parameter (required). `update_record` takes `customer_id`, `field` and `new_value` (all strings, all required); its description is the blank to write.
- `run_agent_loop(user_request)` seeds `messages` with the user request, then loops forever: call `client.messages.create` with the model, `max_tokens=4096`, the tools and messages.
  - `stop_reason == "end_turn"`: return the response.
  - `stop_reason == "tool_use"`: append the assistant turn (`response.content`), then for each `tool_use` block run `execute_tool(block.name, block.input)`, collect a `tool_result` carrying `block.id`, and append those results as a user turn. The second blank sits just before `execute_tool`: "insert HITL checkpoint before executing `update_record`".

## My read of what the gaps need (not the course's model answers)
- **Gap 1, description:** follow the two-part pattern from 02.07/02.08: say when to use it and when not. For example: use it to change one named field on an existing customer record after the record has been read and the change is confirmed; do not use it to look up data (that's `read_record`), to create records, or to change several fields at once; note that the change overwrites the current value.
- **Gap 2, HITL:** inside the `tool_use` branch, before `execute_tool`, check `if block.name == "update_record":` and pause for human approval, showing the customer ID, field, old value and new value. If approved, execute normally. If rejected, don't execute: return a `tool_result` for that `block.id` saying the action was declined (optionally `is_error: true`) so the pairing rule from 02.07 still holds and Claude can continue or explain. This follows 02.16/02.17: gate irreversible writes, and every tool call still gets a matching result.
