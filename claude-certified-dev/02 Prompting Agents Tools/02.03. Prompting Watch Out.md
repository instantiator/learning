# 02.03 Prompting Craft: Watch Out (about 5 min)

Source: Developer Module 2, screen 3 of 29. Title: "The prompt that grew longer instead of better".

## The trap
A prompt can look production-ready and still fail quietly: edge cases drop fields or ignore constraints, usually because the constraint was never stated precisely enough.

## Six-pass trace (same support-ticket classifier as 02.02)
| Pass | What was added | What happened |
|---|---|---|
| 1 | "Classify this as billing, technical, or escalation." | Full sentences ("This appears to be a billing issue"); parser breaks. |
| 2 | "Be concise", "use only the category name" | Case flips between "Billing" and "billing"; router breaks on mismatch. |
| 3 | Three paragraphs describing each category | Fine on easy tickets; ambiguous ones return "billing/technical"; parser breaks on the slash. |
| 4 | "Never return two categories", "if ambiguous pick the most likely" | About 80% of tickets work; tickets that fit two categories get a full explanation instead of a label. |
| 5 | Two more paragraphs on edge cases plus "be precise" | Output balloons past 2,000 characters per call; latency rises, accuracy doesn't. |
| 6 | Replaced everything with a JSON schema plus two few-shot examples | `{"category": "billing"}` every time; parser works, latency drops, accuracy on ambiguous tickets equals pass 4. |

## Two distinct failures
- **Diagnostic failure (pass 4):** the developer misread the problem and added description instead of a constraint.
- **Engineering failure (pass 5):** a long, unfocused prompt induces long, unfocused output because the model matches its response length and style to the input. This can appear even after the first failure is fixed.
- Same cure for both: an output constraint plus two few-shot examples (the constrained prompt from 02.02 with BILLING / TECHNICAL examples).

## Takeaways
- Every pass made the prompt longer and none added the missing output constraint. Claude doesn't need a long description of what a billing ticket looks like; it needs to know the only acceptable answer is one all-caps word.
- The fix is small: an output constraint stating the exact format, and an example covering the ambiguous case.
- Rule of thumb: if three re-prompts in a row haven't worked, stop adding text and work out which technique is missing.
