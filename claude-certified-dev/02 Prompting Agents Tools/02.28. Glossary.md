# 02.28 Glossary: Key Terms (about 3 min)

Source: Developer Module 2, screen 28 of 29. Alphabetical list of the module's terms, restated briefly in my own words.

- **Claude Agent SDK:** a runtime (TypeScript package `@anthropic-ai/claude-agent-sdk`, Python package `claude-agent-sdk`) that gives you the same agent loop that powers Claude Code (iterate, execute tools, observe, terminate), so you can embed an agent in your own product instead of running Claude Code in a terminal. Not the same as the ordinary Anthropic SDK, which is a thin wrapper over the API and runs no agent loop.
- **Context window:** the total tokens a model can handle in one request: system prompt, history, tool definitions, tool results and its own output. At the limit, earlier content must be removed or summarised before more can be added.
- **Function signature:** a function's declaration: its name plus its parameters (names, types, defaults).
- **HITL (human-in-the-loop):** putting a human review or approval step into an automated process before a consequential action.
- **Refactor:** restructuring code internally (reorganising, renaming, rewriting) without changing what it does from the outside.
- **SOC 2:** an audit framework from the AICPA for how a service organisation handles customer data; the standard SaaS and cloud vendors most often cite to show their security practices meet a recognised bar.
- **State:** the information an agent carries between turns: the conversation so far, what the user asked, earlier tool results.
- **stop_reason:** the API response field saying why the model stopped. The two that matter for agent loops: `end_turn` (Claude is finished and wants nothing more) and `tool_use` (Claude issued one or more `tool_use` blocks and is waiting for results).
- **Subagent:** a separate agent instance started by an orchestrating agent for a discrete subtask. It does not inherit the parent's history, skills or context; it starts clean and must be configured explicitly with its instructions and tools, and returns its result to the orchestrator.
- **Token:** the unit Claude measures text in. Characters per token depends on the model's tokenizer and varies between generations, so treat any rule of thumb as model-dependent. Everything in the window consumes tokens (prompts, responses, tool schemas, tool results), and they underlie both pricing and context budgeting.
- **tool_use block:** the content block Claude returns when it wants to call a function: tool name, unique ID and input arguments. It must be answered by a matching `tool_result` in the immediately following user turn, with the ID kept exactly.
