# 02.21 Agent Memory: Checkpoint 7 (about 3 min)

Source: Developer Module 2, screen 21 of 29. Title: "Checkpoint 7: Choose the right memory pattern". A matching exercise, not submitted; the answers below are the ones 02.19 supports.

Match each use case to one memory scope: in-context, external storage (write to a database at session end, read back at the next start), or stateless.

| Use case | Scope | Why |
|---|---|---|
| A customer support agent helps the same user across daily check-ins for two weeks; each session picks up where the last left off | **External storage** | State must survive across sessions. |
| A document formatter takes a file, transforms it, returns the output and terminates; every job is independent | **Stateless** | Nothing to recall; no overhead needed. |
| A coding assistant works with a developer through a multi-hour session that won't continue afterwards | **In-context** | Everything needed lives inside one session and doesn't have to outlive it (watch the window budget; see 02.14). |
