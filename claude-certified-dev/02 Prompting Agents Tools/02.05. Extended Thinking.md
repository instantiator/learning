# 02.05 Extended Thinking: Teaching (about 12 min)

Source: Developer Module 2, screen 5 of 29. Title: "Extended Thinking: turning reasoning on, calibrating effort, and reading it back correctly".

## What it is
Prompting techniques shape *what* Claude produces; extended thinking shapes *how much work* it does first. With it on, the model writes out step-by-step reasoning, then the answer. Your job: decide when the extra work is worth paying for, and handle the reasoning that comes back.

## How it appears in the API
- Reasoning returns as a separate **thinking block** just ahead of the block holding the answer.
- On the newest models the block's content is omitted by default; request a readable summary through the display setting if you need to see it.
- On current models reasoning is **adaptive**: enable it with the `thinking` parameter (where it isn't already on by default) and the model decides how much to think per request. Tune depth with the **effort** setting, not a fixed token budget.
- The older `budget_tokens` control is deprecated and returns a 400 on the newest generations.
- Cost: thinking tokens are billed like output tokens, so high effort on a simple task is paying for accuracy you don't need. Match the tool to the task; don't enable it by default.

## When to use it
| Task shape | Call | Why |
|---|---|---|
| Multi-step reasoning with several constraints held at once (derivations, multi-hop logic, planning dependent actions) | Enable; match effort to the problem's depth | The reasoning pass works through dependencies it would otherwise skip. |
| Mechanical or lookup tasks (classification, format conversion, field extraction, short facts) | Leave off | No accuracy gain, more tokens; a bare prompt with an output constraint is right. |
| Agent loops planning across several tool calls | Enable; budget for the planning step, not per call | Reasoning before the plan reduces wrong-tool selection later. The carry-back rule applies. |

## The carry-back rule
When thinking is on **and** the conversation uses tools, every thinking block must go back to the API exactly as received on the next turn.
- Each block carries a signature proving it wasn't altered. Edit, summarise or drop it and the signature no longer matches, so the API rejects the request.
- Redacted thinking blocks (encrypted, unreadable) must also be returned untouched.
- This is a structural requirement, not a prompting choice. Common mistake: stripping thinking blocks to save context, which breaks the next request. If the worry is accumulated reasoning filling the context, the answer is context engineering (later in this module), not deleting blocks.

## Scope note
This lesson covers enabling reasoning and setting effort. Choosing *which model* to run is separate and was taught in Module 1 (see 01.03).

## Summary box
- **Handles well:** hard reasoning and planning where a wrong answer is expensive and extra tokens buy accuracy.
- **Adds cost or complexity:** the carry-back requirement in tool loops, plus an effort setting you now have to calibrate.
- **Use something else:** for classification, extraction and format tasks, a well-constrained prompt is cheaper and just as accurate.
