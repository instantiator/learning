# 02.12 Streaming: Checkpoint 4 (about 4 min)

Source: Developer Module 2, screen 12 of 29. Title: "Checkpoint 4: Repair the broken stream handler". A write-your-answer exercise, not attempted, so the course's model answer was not revealed.

## The task
A handler streams a response and appends the assistant turn to history. It has one defect that only shows up when a stream is interrupted. Identify it and write the corrected version.

## The broken handler (described, not copied)
Python using the SDK's streaming context manager:
- it starts with an empty `blocks` dict and a `stop_seen = False` flag;
- it iterates the stream events: on `content_block_start` it creates a block at that index; on `content_block_delta` it applies the delta to that block; on `message_stop` it sets `stop_seen = True`;
- after the loop it **always** appends `{"role": "assistant", "content": assemble(blocks)}` to `messages`.

## My read of the defect (not the course's model answer)
`stop_seen` is recorded but never used. The history append runs whenever the loop exits, so an interrupted stream commits a half-built turn (possibly a `tool_use` with truncated JSON), which is exactly the failure from 02.11.

The fix in the spirit of 02.10/02.11:
- gate the append on `stop_seen` (equivalently, only append after `message_stop`);
- if the stream ended without it, discard the partial `blocks`, don't touch `messages`, and retry from the last complete turn (also treat an exception from the stream the same way);
- optionally check `stop_reason` from `message_delta` before continuing a tool loop.
