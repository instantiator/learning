# 02.26 Multimodal and Batch Ingestion: Checkpoint 8 (about 3 min)

Source: Developer Module 2, screen 26 of 29. Title: "Checkpoint 8: Select the right input encoding for each scenario". A matching exercise, not submitted; the answers below are the ones 02.24 supports. The course says each item's feedback names the cost of the wrong choice.

Options per scenario: Message Batches API (submit all in one batch call, poll), Files API (upload once, reference a `file_id`), or inline base64 (encode into the message block).

| Scenario | Choice | Why |
|---|---|---|
| A reference product diagram used in every request your pipeline makes | **Files API** | Same asset reused across requests: upload once, send only the ID, instead of resending the bytes every time. |
| A one-off screenshot of a UI bug, submitted by a support engineer in a single request | **Inline base64** | Single use; an upload step adds complexity for no payoff. |
| A job classifying 5,000 customer feedback responses | **Message Batches API** | High-volume, offline, no user waiting; cheaper and asynchronous (and see 02.25 for why a synchronous loop isn't batching). |

Note: the first two choose how to *send an asset*; the third chooses a *submission model*. They aren't strictly one category, which is why Batches appears as an option alongside the encodings.
