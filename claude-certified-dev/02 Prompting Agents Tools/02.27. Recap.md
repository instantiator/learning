# 02.27 Recap: Eight Takeaways (about 3 min)

Source: Developer Module 2, screen 27 of 29. One takeaway per learning goal.

1. **A failed prompt's failure type tells you which technique is missing.** Wrong shape means no output constraint; drift across turns means a vague system prompt; invented structure means no few-shot examples. Rewording rarely helps because these aren't phrasing problems: diagnose, then add the matching technique. If untested inputs still break the parser, move control into the API with structured outputs: JSON outputs constrain the final response to a schema, and strict tool use validates the arguments Claude passes to tools. Costs: first-call schema compilation latency and extra input tokens. (02.02 to 02.04)
2. **Match reasoning depth to the task before tuning the prompt.** Enable reasoning only where it changes the answer, calibrate the effort setting rather than raising it everywhere, and return thinking blocks unchanged or the next request fails. Choosing the *model* is a separate matter from Module 1. (02.05, 02.06)
3. **A stream ending is not a message completing.** Streaming buys perceived speed at the cost of assembling the response yourself. Act on a block only after it closes, commit a turn to history only after `message_stop`, and on interruption discard the partial turn and retry. A tool-use error on a retry may trace to a half-built block from a dropped stream, not the schema. (02.10 to 02.12)
4. **Wrong-tool selection traces back to the schema, usually the description.** Two tools that both say "use this to find information" are indistinguishable to Claude even if their input schemas differ. The one sentence that fixes most cases is an exclusion condition in every description, written at design time. MCP lets you connect a maintained server instead of writing every schema, but each connected server's tool definitions occupy the window whether used or not, so connect deliberately and control loading cost. (02.07 to 02.09)
5. **Context is a fixed budget, and tool outputs spend it fastest.** Production tool output is often 3 to 5 times longer than development fixtures, so a session that holds for fifty turns in testing can hit the ceiling at turn eight. Pruning, compaction and subagent handoffs each buy headroom differently; pick by whether you still need the earlier state. If tool selection degrades after a fixed number of turns, check the window first, not the schema. (02.13 to 02.15)
6. **The workflow-or-agent choice sets the cost of everything after, and human checkpoints belong in the design.** Workflow when you can write the exact steps in code; agent when you can specify the goal and tools but not the path. Wrong either way only shows in production: agents where workflows suffice add context cost and transcript-only behaviour; workflows where agents are needed break on the first input off the path. Add the HITL checkpoint for irreversible actions before wiring the loop, not after the first write reaches a customer. (02.16 to 02.18)
7. **Memory scope follows the shape of the session, not what's easiest to build.** In-context is simplest but fails earliest when production sessions are shorter and more numerous than development's long ones. External storage adds latency but survives sessions; summarised memory cuts cost but loses what the summariser didn't keep; stateless suits jobs that close out. The refactor from in-context to external under pressure takes about an hour; the same decision made at design time about twenty minutes. Carrying repeatable instructions is a different problem from carrying state; the pattern is a Skill, a markdown file loaded on demand by matching its description. (02.19 to 02.21)
8. **Cost a multimodal input before writing ingestion code, and match the API to the workload.** An image costs ceil(width/28) x ceil(height/28) visual tokens and the per-image ceiling varies by tier; run the formula on the largest production input, not the test set. Inline base64 for one-offs, the Files API for assets reused across requests, the Batches API for offline work at lower per-token cost with non-deterministic latency. Don't call the synchronous API in a loop and call it batching. (02.24 to 02.26)
