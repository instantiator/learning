# 05.09 Requirements & Lifecycle: Checkpoint 1 (about 2 min)

Source: Developer Module 5, screen 9 of 25. Title: "Checkpoint 3: extract the requirements". Quiz not submitted, so the course's answer key wasn't revealed; the answers below are my own reading of 05.08.

## Scenario
A regulated EU bank wants an agent that summarises customer call transcripts for its support team, with summaries reviewed before they are stored in the EU.

## Q1: valid functional requirement?
- A. "The agent should be fast and accurate." (vague, not checkable)
- **B. "The agent produces a summary that a human approves before it is stored."** ← my answer: a checkable behaviour
- C. "The system must be built using an approved cloud provider." (platform constraint)
- D. "Transcript data must not leave the EU." (residency, an infrastructure constraint)

## Q2: valid infrastructure requirement?
- A. "Quickly enough for support staff to act on them." (latency is infrastructure, but this wording is vague and unmeasurable)
- B. "Summarises using a pre-approved prompt template." (behaviour/design)
- **C. "Transcript data is processed in the EU."** ← my answer: residency, one of the four infrastructure questions (latency, scale, residency, identity)
- D. "A human reviews each summary before it is stored." (functional)

Rule of thumb: functional = what the system does, stated checkably; infrastructure = latency, scale, residency, identity constraints, each traceable to a regulation or need.
