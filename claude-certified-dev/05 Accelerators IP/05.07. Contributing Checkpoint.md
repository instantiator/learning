# 05.07 Contributing Back: Checkpoint (about 3 min)

Source: Developer Module 5, screen 7 of 25. Title: "Checkpoint 2: Choose the contribution channel and the readiness fix". Exercise not attempted (nothing submitted), so the course's answer key wasn't revealed; the matches below are my own reading of 05.05.

## The task
Three cases; match each to (1) the channel built for it and (2) the one readiness item its snippet is missing.

- **Case A:** a focused tool wrapping a single API into a clean function; the snippet is just the function.
- **Case B:** a full customer-service application shared whole, including UI and deployment scripts.
- **Case C:** a one-line fix to an existing Cookbook example, carried in from a customer engagement.

## Options offered
- Channels: the tool's own repository / the Cookbook, but only after the reusable pattern is stripped out as a focused example / the Cookbook example's own repository.
- Readiness items: a test that proves the wrapper behaves / reduction to a single focused pattern (a whole app doesn't fit a review built for one pattern) / the rights check (engagement code can carry a licensing constraint that blocks the merge before any technical review).

## My matches
| Case | Channel | Missing readiness item | Why |
|---|---|---|---|
| A | The tool's own repository | A test proving the wrapper behaves | Tools and servers live in their own repos; the snippet is only the function, with no test (05.05) |
| B | The Cookbook, after stripping the reusable pattern out as a focused example | Reduction to a single focused pattern | The Cookbook reviews one pattern, not a whole app (05.05) |
| C | The Cookbook example's own repository | The rights check | A fix to an existing example goes where that example lives; code carried from an engagement may have licensing limits, and rights come before technical review |
