# 05.14 Deployment & Versioning: Checkpoint (about 4 min)

Source: Developer Module 5, screen 14 of 25. Title: "Checkpoint 5: Match the deployment platform and version pin to each scenario". Not submitted, so the course's answer key wasn't revealed; the picks below are my own reading of 05.12.

## The task
A customer runs AWS with a data-residency requirement and needs to roll back a model update. Pick one piece per group to assemble the minimal deployment configuration; leave out what doesn't belong.

| Group | Options | My pick | Why |
|---|---|---|---|
| Platform | First-party API / Amazon Bedrock / Google Vertex AI | **Amazon Bedrock** | Customer is on AWS; data stays in their AWS boundary, with regional routing for residency |
| Identity | AWS identity reference / Anthropic API key | **AWS identity reference** | Bedrock uses AWS identity; identity comes from the platform |
| Model reference | A pinned full model ID / A moving alias | **A pinned full model ID** | Makes upstream updates a deliberate choice |
| Rollback | Retain the prior pinned version / No retention | **Retain the prior pinned version** | Makes a regression a rollback, not a hotfix |
