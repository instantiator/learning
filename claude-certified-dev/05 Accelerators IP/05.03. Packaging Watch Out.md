# 05.03 Packaging for Reuse: Watch Out (about 2 min)

Source: Developer Module 5, screen 3 of 25. Title: "The template that shipped fast and could not be reused". Written as a postmortem.

## What happened
Under deadline, a team shipped an agent template with customer-specific values hardcoded into the loop: repository path, model name, review thresholds, and prompt fragments specific to the customer's domain. It ran, the engagement closed, and it went into the shared repo labelled reusable.

Months later a second team couldn't configure it: nothing was configurable, every value was baked into the loop, there was no document saying which values were customer-specific vs load-bearing, and no bundled eval to confirm it still worked in the new context. They rewrote it from scratch.

## Why it broke
The build was treated as finished when it ran, not when it could be reused. Hardcoding was a reasonable call under a deadline and was never revisited. A working template doesn't announce it can't be reused; the cost showed up only when a second team paid for the rebuild packaging should have prevented.

## What to watch for
A template that runs hasn't been packaged for reuse; these are different finishing states. Warning signs are the absence of: parameters where customer-specific values belong, documentation of assumptions, and a bundled eval proving it still works in a different context. Package while the build is fresh, because knowing what is customer-specific is most expensive to reconstruct after the people who knew have moved on.
