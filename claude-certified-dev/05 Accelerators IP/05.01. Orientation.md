# 05.01 Orientation (about 2 min)

Source: Developer Module 5, screen 1 of 25. Title: "What you will be able to do by the end".

Module 5 (25 screens, 9 sections, about 139 min, 9 checkpoints) picks up once a build works. Either you rebuild it from scratch on the next engagement, or you package it once so the next team just configures it, which frees time for new work. Document the build well and the next engagement builds from it.

## Outcomes
1. Package a working solution as a reusable **accelerator**: a parameterised agent template, a configurable MCP server, or a portable eval suite.
2. Contribute a tool, pattern or fix back through documented channels, prepared so a maintainer can accept it (private asset becomes shared infrastructure).
3. Choose where a Claude workload runs (first-party API, Amazon Bedrock, Google Vertex AI, third-party platforms) and version what ships so a model or prompt change can't silently break production.
4. Compare platforms on latency, compliance and cost so procurement and security can sign off on a deliberate choice, not a default.
5. Build an application coordinating several Claude deployments into one workflow, scoped so data and identity boundaries hold under security or compliance review.

## Audience and theme
For the Developer with a working build who must make it last: practical, code-forward, pattern-oriented. Earlier modules (production agent, Claude Code setup, MCP connections, evals) are assumed, not retaught.

Recurring gap: **a build that works is not yet a build that survives reuse, review or deployment.** The template must be configurable by a team that never spoke to you; a contribution must be verifiable by a maintainer who reconstructs nothing; the model must be pinned so an upstream change is a decision, not a surprise; the platform must clear a customer's residency and compliance review; connected platforms must hold trust boundaries under audit. Many of these decisions are driven by the customer's existing cloud, compliance posture and review process. The point where code starts working is where this module's work begins.
