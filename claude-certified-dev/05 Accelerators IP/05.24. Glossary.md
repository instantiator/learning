# 05.24 Glossary: Key Terms (about 3 min)

Source: Developer Module 5, screen 24 of 25. Title: "Key terms from this module".

| Term | Meaning |
|---|---|
| Accelerator | A working solution packaged so the next engagement configures it rather than rebuilding it. Customer-specific parts are exposed as documented parameters, assumptions are written down, and an eval is bundled to prove it still works in a new context. |
| Contribution readiness | What a maintainer needs to verify a contribution: focused code, a runnable example, a test that proves the behaviour, a statement of environment assumptions, and confirmed rights to contribute the code. |
| Deployment platform | Where a Claude workload runs. Six: the first-party Claude API, Claude Platform on AWS, Claude in Amazon Bedrock, Claude on Amazon Bedrock (legacy), Google Vertex AI, and third-party platforms. The same model can differ by platform on identity, data residency, latency and cost. |
| Model alias vs pinned ID | An alias such as `opus` or `sonnet` resolves to a recommended version that updates over time and can differ by platform. A pinned full model ID is a fixed snapshot. Pinning keeps an upstream model change from being a silent production change. |
| Trust boundary | The seam where data or instructions move from one deployment environment to another in a multi-component app. Content fetched by one component is untrusted when it reaches the next, so the receiver treats it as data, not instructions. |
