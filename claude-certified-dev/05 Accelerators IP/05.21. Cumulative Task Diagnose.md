## The task
A runnable packaged accelerator deployed across platforms has three planted defects: one in packaging, one in deployment and versioning, one in the multi-component boundary layer. Find all three; the corrected lines carry into the next screen (05.22).

## The code as shipped
```python
# Packaged code-review accelerator, deployed for a regulated AWS customer
def build_agent():
    return Agent(
        model="opus",
        system_prompt=SYSTEM_PROMPT,
        repo_path="/home/acme/checkout",
        tools=[read_file, run_linter],
    )
deploy(platform="amazon_bedrock", identity=aws_role_arn)

# multi-component step: Claude Code task fetches a customer page
fetched = code_task.run(fetch_url=customer_page)
next_call(input=fetched)
```

## My analysis
| # | Layer | Defect | Fix |
|---|---|---|---|
| 1 | Packaging | `repo_path="/home/acme/checkout"` is a customer-specific value hardcoded into a "reusable" asset (05.02-05.04) | Take `repo_path` as a parameter: `def build_agent(repo_path): ... repo_path=repo_path` |
| 2 | Deployment and versioning | `model="opus"` is a moving alias, not a pinned full model ID, and there's no retained prior version (05.12-05.13) | Pin the full model ID (in the Bedrock ID format) and keep the prior pinned version for rollback; gate promotion on the eval |
| 3 | Multi-component boundary | `next_call(input=fetched)` passes untrusted fetched content straight into the next call, so any embedded instructions are followed (05.18-05.19) | Treat it as data at the seam: `next_call(input=treat_as_data(fetched))`, with least-privilege scoping on the components behind it |

The platform choice (Bedrock for a regulated AWS customer) and AWS identity look right, so they don't appear to be defects.
