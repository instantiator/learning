# 04.22 Glossary: Key Terms (about 3 min)

Source: Developer Module 4, screen 22 of 23. Title: "Key terms from this module".

| Term | Meaning |
|---|---|
| Agentic search | The model issues its own queries, reads results and refines over several rounds, instead of fetching a fixed context once. Handles multi-step questions and changing corpora at higher token and latency cost; avoids index staleness and infrastructure. |
| Eval | A set of input cases, expected behaviours and grades defining what a feature must do before shipping. Running it gives a score on a holdout set, turning "done" into a trackable number as prompt, tools or model change. |
| Exponential backoff | Waits a growing interval between retries, up to a cap and a fixed number of tries, often with random jitter. Stops immediate retries deepening a rate limit; honours a retry-after value if given. |
| Hook-based guardrail | A check at a fixed point in the Claude Code agent lifecycle (e.g. `PreToolUse`) that can block an action and log it. Unlike a prompt instruction it is enforced before the action, which is what regulated reviews care about. |
| Integration test | Exercises the seam where two components hand off (e.g. retrieval output into a model call). Catches silent failures unit and functional tests miss, since each part can pass alone while the handoff is wrong. |
| LLM-as-judge | A second model call with a rubric scores open-ended output no code rule can check. Returns a score with reasoning; trustworthy only after calibrating against human-labelled cases and measuring agreement. |
| Orchestrator-worker pattern | A lead agent plans, spawns parallel subagents (each with its own context) and compiles results. Helps broad tasks that split into independent parts, at roughly 15x the token cost of a single chat in Anthropic's reported case. |
| Prompt injection | Instructions hidden in fetched content get treated as commands because the model reads its whole context as one stream with no trusted/untrusted boundary. Defence: treat fetched content as data and enforce the action boundary outside the prompt. |
| Retriable vs terminal error | Retriable (rate limit, overload) will probably succeed later, so back off and retry. Terminal (bad request) will fail identically again, so fail fast and don't spend the retry budget. |
