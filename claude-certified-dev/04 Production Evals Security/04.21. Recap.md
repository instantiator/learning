# 04.21 Recap: Key Takeaways (about 3 min)

Source: Developer Module 4, screen 21 of 23. Title: "Key takeaways".

1. **Set the standard before you build it.** An eval turns "done" into a score on a fixed set of cases. Match the grading to the output: exact match when there is one correct form, a code check for structured output, a judge for open-ended quality (calibrate the judge against human-labelled cases first). Write the eval first so success is defined while the design can still change.
2. **Match the test to the failure; trace to find where it happened.** Unit, functional, integration and end-to-end tests each catch a different break; most silent failures hide at the integration seam where two passing components hand off. A trace shows which step produced the bad result. Same instinct for retrieval: fetch once for single-fact lookups, search iteratively for genuinely multi-step questions.
3. **Sort every failure, then handle each individually.** First ask whether waiting and retrying could fix it. Retriable failures get exponential backoff with a cap and a retry budget, never an immediate loop. Tool failures go back to the model with the error flag set, not hidden behind an empty result it mistakes for data. Every failure a retry can't fix needs a named fallback; otherwise an unhandled exception becomes the default behaviour and one bad response takes down the flow.
4. **Measure cost and latency per call; fan out only when a task truly splits.** Instrument token cost, latency and error rate on every call, then tune a chosen lever. Orchestrator-worker multiplies token cost by the number of subagents (roughly 15x in Anthropic's reported case); it pays off only for independent parallel parts, not tightly coupled work a single agent can do far cheaper.
5. **Treat fetched content as data and enforce the boundary with a hook.** The model reads everything as one token stream with no built-in trusted/untrusted line. Trusting your users doesn't help since injection arrives via content. Examine untrusted input as data, scope identity to least privilege, keep secrets out of committed config, and enforce the action boundary with a hook that blocks and logs before the tool runs.
