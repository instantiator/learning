## The task
Earlier screens hardened one layer at a time, but real production failures rarely arrive one at a time. A single runnable app has three planted defects, each from a different layer group. Localise each to its layer, then fix and integrate all three.

## The code (paraphrased)
```python
def answer(question, page_url):
    page = fetch(page_url)                       # untrusted content
    notes = read_file("/workspace/input/notes")
    write_file(page.suggested_path, summarize(page))
    resp = None
    for i in range(5):
        try:
            resp = client.messages.create(model=MODEL, max_tokens=MAX_TOKENS,
                                          messages=msg(question))
            break
        except Exception:
            time.sleep(0)
    return resp.content[0].text
```

## Defects (my analysis)
| # | Defect | Layer | Runtime effect |
|---|---|---|---|
| 1 | `write_file(page.suggested_path, ...)`: the path to write comes from the fetched, untrusted page, with no check | Security | A hostile page picks where the agent writes (injection / exfiltration). Fix: treat the page as data, use a fixed permitted path, and add a `PreToolUse` hook that denies writes outside it, with an audit log. |
| 2 | Retry loop: bare `except Exception` with `time.sleep(0)`: retries instantly, for every error type, no backoff | Failure handling | Hammers the API during a rate limit or outage, and retries non-retryable errors; after 5 fails `resp` is `None` and `resp.content[0]` crashes. Fix: retry only retryable errors (429/5xx/overloaded) with exponential backoff plus jitter, and handle final failure explicitly. |
| 3 | A cost/orchestration problem: a hard-coded `MODEL` and `MAX_TOKENS` for every request, with no model routing or token limits sized to the task (inferred; also `notes` is read but never used) | Cost and orchestration | Overspend at scale (frontier model and large output cap for simple work). Fix: pick the model by task difficulty and set `max_tokens` to the realistic output size. |

Note: the three layers are named by the screen's own framing ("one per layer", from the groups of eval, test/tracing, failure, cost/orchestration, security). Defect 3's identity is my inference; the eval or testing layer (no check that the output is correct) is another candidate.
