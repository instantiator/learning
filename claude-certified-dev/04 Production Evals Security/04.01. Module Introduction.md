## Framing
You've built agents that work (Modules 2 and 3). This module is about proving they keep working under production traffic: when an untested edge case arrives, a rate limit hits peak, or a fetched web page carries a hidden instruction, does the system hold or fail quietly? It turns "works on my machine" into something you can defend in a review.

## Learning goals
1. **Evals:** write an eval suite that defines "done" for a Claude feature before deployment, pick the grading method that fits the task, and calibrate an LLM-as-judge against human-labelled cases so the result is defensible.
2. **Testing and tracing:** a layer that catches regressions at unit, functional, integration and end-to-end levels.
3. **Failure handling:** make the application resilient by separating retriable errors from terminal ones.
4. **Cost and orchestration:** keep the system inside its cost, latency and reliability budget, including when work spans several coordinating agents, by instrumenting each call and using parallel agents only when the task needs them.
5. **Security:** defend against prompt injection, jailbreaks, untrusted input, scoped identity, exposed secrets and data-boundary problems so the deployment survives a security or compliance review.

## The recurring gap ("the build")
Development hides the failures production reveals: the feature gave the right answer the few times you tried it, every call succeeded because traffic never hit a limit, the corpus fit in the window, and the agent only read content you wrote. Production brings an untested input shape, a rate limit at peak, a corpus too large to load, and a fetched page aimed at the agent. The failure is rarely a bug in code that ran; it's a **decision never made**: success never written down as a graded set, the retriable case never given a path, the budget never instrumented, the action boundary never enforced. The module's work is making each of those decisions on paper before the failure shows up live, and capturing them in a design document the rest of the build reads from. Each layer (eval, test and trace, failure path, cost budget, security boundary) closes one way the development-to-production gap becomes a quiet production failure.
