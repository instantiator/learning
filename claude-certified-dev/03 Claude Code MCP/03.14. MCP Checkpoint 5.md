# 03.14 MCP Servers: Checkpoint 5 (about 4 min)

Source: Developer Module 3, screen 14 of 22. Title: "Checkpoint 5: match transport and scope to each deployment scenario". A matching exercise, not submitted; the answers below are the ones 03.12 supports. Options per scenario: HTTP + Project (`.mcp.json`); HTTP + Enterprise (managed settings); stdio + Local; stdio or HTTP + Local.

| Scenario | Match | Why |
|---|---|---|
| A local SQLite query tool you use only on your development machine | **stdio + Local** | It runs as a local subprocess on your own machine; a stdio server can't be shared, so local scope. |
| A code search service hosted on company infrastructure that the whole engineering team should access | **HTTP + Project (`.mcp.json`)** | Remote service, so HTTP; committed `.mcp.json` gives everyone who clones the repo the same server. (Keep any key out of the file, 03.13.) |
| An experimental web-scraping server you're testing this week against one repository, not ready to share | **stdio or HTTP + Local** | Personal and unshared, so local scope; either transport depending on how it runs. |
| A security-scanning server IT needs deployed to every developer's Claude Code installation | **HTTP + Enterprise (managed settings)** | Organisation-wide, administrator-controlled and locked against override: enterprise scope, remote HTTP. |

Rule of thumb from 03.12: decide transport by where the server runs, then choose scope by who should load it.
