# 03.11 Packaging Workflows: Checkpoint 4 (about 4 min)

Source: Developer Module 3, screen 11 of 22. Title: "Checkpoint 4: fix the broken plugin definition". A two-part multiple-choice exercise, not submitted; the answers below are the ones 03.10 supports.

## The scenario
A `SKILL.md` works on the author's machine but will fail when a teammate clones the project and installs the plugin. The skill is named `deploy-validate`, with the description "Validates a deployment configuration before release". Its steps: (1) run a validation script at an absolute path under the author's home directory (`/Users/<author>/projects/deploy-utils/validate.sh`); (2) if the script exits non-zero, report the error to the developer; (3) if validation passes, confirm the deployment configuration is safe to proceed.

## Part 1: the single defect
Options: (A) skill name doesn't match the plugin name; (B) description too short to match; (C) the absolute path in step 1; (D) step 2 should report to the user rather than the developer.
**Answer: (C).** The path exists only on the author's machine, exactly the failure in 03.10. The other options aren't what breaks on a teammate's machine.

## Part 2: the correct fix
Options: (A) reference the script from the project root using `CLAUDE_PROJECT_DIR`, so it resolves wherever the project is cloned; (B) another absolute path, on a shared network drive; (C) a home-directory shortcut (`~/projects/deploy-utils/validate.sh`); (D) delete step 1.
**Answer: (A).** Build the path from `$CLAUDE_PROJECT_DIR` (or `${CLAUDE_PLUGIN_ROOT}` if the script ships inside the plugin). A network-drive path is still machine-specific; `~` still depends on each person's home layout; deleting the step removes the validation instead of fixing it.
