# 03.07 Durable Project Context: Checkpoint 2 (about 3 min)

Source: Developer Module 3, screen 7 of 22. Title: "Checkpoint 2: drag the correct value". A fill-the-blanks exercise, not submitted; the answers below are the ones 03.05 supports.

## The task
Set up a hook that enforces a path restriction: a `hooks` config whose entry, keyed by a lifecycle event, has matcher `Read` and a `command` hook. Two blanks: the lifecycle event, and the command that blocks reads of `.env.production`.

## Blank 1: the lifecycle event
Options: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `SessionStart`.
**Answer: `PreToolUse`.** It runs before the tool call executes, so it's the only one of these that can stop the read. `PostToolUse` runs after the call has already happened and can't block; `UserPromptSubmit` and `SessionStart` fire at other points and don't see the individual tool call.

## Blank 2: the command
Options: (a) a script that reads the tool call from stdin, checks the file path, and exits with code 2 when the path is `.env.production`, writing the reason to stderr; (b) a script that logs the call to an audit file and exits 0; (c) a script that prints a warning and exits 0 unconditionally.
**Answer: (a).** Exit code 2 is what blocks a `PreToolUse` call, and the stderr reason is the feedback the agent sees. (b) and (c) always exit 0, so the read goes ahead.

Connects to: 03.04 (deny rules for `.env.production`), 03.06 (the rule you can't afford to dilute should become a hook).
