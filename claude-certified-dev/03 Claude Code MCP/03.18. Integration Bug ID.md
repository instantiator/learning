# 03.18 Cumulative Integration Task: Bug ID (about 6 min)

Source: Developer Module 3, screen 18 of 22. Title: "Cumulative integration task: checkpoint". Stage 1 of 2; the assembly stage is screen 19. A write-your-answer exercise, not attempted, so the course's model answer was not revealed.

## The task
Three files hide three bugs, one per layer the module covers: Claude Code configuration, plugin/packaging, and MCP/authentication. For each file, identify the bug and write one sentence on what it does or fails to do at runtime.

## The three files (described, not copied)
1. `.claude/settings.json`: sets `permissions.defaultMode` to `bypassPermissions` and has a deny rule for `Read(.env.production)`.
2. `.claude/skills/migration-validate/SKILL.md`: skill `migration-validate`, described as validating migration scripts before they run against production. Step 1 runs a script at an absolute path under a person's home directory (`/Users/priya/scripts/validate-migration.sh`); step 2 reports the results.
3. `.mcp.json`: an `http` server `data-warehouse` at an internal URL with an `Authorization: Bearer` header holding a literal production key.

## My read of the bugs (not the course's answer)
1. **Configuration layer, `settings.json`:** `bypassPermissions` as the default mode removes every confirmation and the protected-path guard, so only the single deny rule stands between the agent and everything else (03.02, 03.03). A project-shared file should not default to bypass. Better: `default` or `acceptEdits`, with deny rules for sensitive paths and destructive commands, and bypass only inside a disposable container or VM.
2. **Packaging layer, `SKILL.md`:** the absolute path to one person's home directory exists only on their machine, so the skill fails for every teammate who installs it (03.10, 03.11). Use `$CLAUDE_PROJECT_DIR` (or `${CLAUDE_PLUGIN_ROOT}` if bundled) and bundle or share the script.
3. **MCP/authentication layer, `.mcp.json`:** a production API key written inline in a committed file lands in repository history and every clone; it must be treated as compromised and rotated (03.13). Reference an environment variable instead (for example `Bearer ${WAREHOUSE_MCP_TOKEN}`), and consider a `PreToolUse` hook that blocks inline credentials.
