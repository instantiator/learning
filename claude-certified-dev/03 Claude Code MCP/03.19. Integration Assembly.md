## The task
Write the complete corrected content of the three files from 03.18: `settings.json`, `SKILL.md` and `.mcp.json`.

## My suggested corrected versions (not the course's model answer)
These follow the bugs identified in 03.18.

**1. `.claude/settings.json`**: replace the bypass default and keep the deny rule, adding denials for destructive commands:
```json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": ["Bash(npm run:*)"],
    "deny": ["Read(.env.production)", "Bash(rm:*)", "Bash(git push:*)"]
  }
}
```
Why: `acceptEdits` (or `default`) keeps safety prompts and the protected-path guard; deny rules win in every mode (03.02, 03.04). Bypass belongs only in a disposable container or VM.

**2. `.claude/skills/migration-validate/SKILL.md`**: same name and description, but build the script path from the project or plugin root:
```markdown
---
name: migration-validate
description: Validates migration scripts before they run against production.
---
## Steps
1. Run: "$CLAUDE_PROJECT_DIR/scripts/validate-migration.sh"
   (or "${CLAUDE_PLUGIN_ROOT}/scripts/validate-migration.sh" if the script ships inside the plugin)
2. Report validation results.
```
Why: an absolute home-directory path fails on every other machine; the script must also be bundled or committed in a shared location (03.10, 03.11).

**3. `.mcp.json`**: keep the server address, replace the literal key with an environment-variable reference:
```json
{
  "mcpServers": {
    "data-warehouse": {
      "type": "http",
      "url": "https://warehouse.internal/mcp",
      "headers": { "Authorization": "Bearer ${WAREHOUSE_MCP_TOKEN}" }
    }
  }
}
```
Why: the committed file holds only the address and a variable name. Because the original key was committed, treat it as compromised and rotate it; inject the new value as an environment variable or from a secret store (03.13, 03.15). Optionally add a `PreToolUse` hook that blocks inline credentials in `.mcp.json`.
