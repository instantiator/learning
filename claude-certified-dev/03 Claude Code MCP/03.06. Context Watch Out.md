# 03.06 Durable Project Context: Watch Out (about 4 min)

Source: Developer Module 3, screen 6 of 22. Title: "The CLAUDE.md that kept growing until the rules stopped landing".

## The trap
Every new rule felt worth adding to `CLAUDE.md`, and each addition was individually reasonable. Over a few weeks the file passed 800 lines.

## The incident (composite session log)
- The project's `CLAUDE.md` had accumulated for two months: 847 lines covering framework preferences, testing conventions, a style guide, dependency rules, path restrictions (one line, around line 347: do not modify files in `/legacy/tokens/`), a long historical-decisions log (about lines 361 to 700), and archived notes.
- The user asked for an auth-module refactor to use the new token service and said explicitly not to modify `/legacy/tokens/`.
- Claude edited the auth service, read `/legacy/tokens/store.ts` for reference, then **edited it** to update the token interface, breaking the instruction. When challenged it apologised and said it hadn't flagged the conflict.
- The rule was in the file and the agent had access to it. The failure was **dilution**: 846 other lines reduced the effective weight of the one that mattered. The decision log and archived notes needed recording somewhere, but not in `CLAUDE.md`.

## Takeaways
- `CLAUDE.md` is a working set of rules that change behaviour in the current session, not a growing append log. Every added line lowers the weight of every other line.
- Path-specific rules belong in rules files scoped by `paths` (03.05). Historical context belongs in a separate reference document the agent reads on demand.
- When the file passes a few hundred lines, audit it: keep what is truly session-critical, move the rest.
- The one rule you can't afford to dilute should be the shortest path to a **hook**: a `PreToolUse` hook blocking edits under `/legacy/tokens/` would have enforced it every time, regardless of how much text sat around it.
