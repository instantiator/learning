# 03.03 Permission Modes: Watch Out (about 3 min)

Source: Developer Module 3, screen 3 of 22. Title: "The bypass mode that removed the one prompt that mattered".

## The trap
You switch to `bypassPermissions` to stop the constant prompts because the work feels routine: the agent has behaved for days, the cleanup is simple, and a prompt before every tool call feels like friction.

## The incident (composite pairing session)
- A codebase cleanup had run for three days without trouble. The developer switched to `bypassPermissions` to rename old API endpoint references: "nothing risky".
- Claude scanned for files matching the pattern `/v1/legacy/` (47 found), updated references, then ran a `cleanup.sh` post-rename script.
- The script deleted three files matching the pattern in `/deploy/config/prod/`: production environment-specific endpoint overrides. The developer had meant to work only in `/src/`.
- The pattern matched in both places. In bypass mode no confirmation was requested before the deletions.

## Diagnosis
The prompt that would have caught this was switched off along with everything else. In `default` or `acceptEdits`, running the cleanup script would have required a confirmation, giving the developer a chance to stop it before it touched production config.
Precision on where the gate sits: it was the **script invocation** that would have prompted, not the `rm` deletions themselves. `acceptEdits` auto-approves common filesystem commands including `rm` on paths inside the working directory, so had Claude issued the deletes directly, `acceptEdits` would have let them through silently; only `default` prompts for those.

## Takeaways
- A bypass mode silences every confirmation, including ones you didn't anticipate. The pattern: an agent matches a broader set of files than intended, in a mode with no checkpoints.
- `bypassPermissions` also skips the protected-path guard the other modes keep, so even repo state and Claude's own configuration lose their automatic prompt.
- Cover the gap with **deny rules on sensitive directories before switching modes** (deny beats allow in every mode; see 03.02).
- If you want fewer prompts without losing the safety net, use a classifier-gated mode such as `auto` rather than a full bypass.
