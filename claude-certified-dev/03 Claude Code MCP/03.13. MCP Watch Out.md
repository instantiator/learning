# 03.13 MCP Servers: Watch Out (about 4 min)

Source: Developer Module 3, screen 13 of 22. Title: "The API key that traveled with the configuration file into the repository".

## The trap
The server worked, the team needed a shared setup, and tidying the authentication felt like something to do after the handoff. That shortcut turned a temporary hard-coded key into a shared credential exposure the moment the config file was committed.

## What happened (composite)
- A developer connected to a data-warehouse MCP server with a service-account API key and, to get it working fast, put the key directly in `.mcp.json`, planning to move it to an environment variable before sharing.
- They then committed `.mcp.json` so teammates could connect by cloning, and the key went with it. Within 48 hours three teammates had cloned the repo and a CI pipeline had made a fresh clone: the key now sat on the author's machine, in repository history, on three teammate machines and on the CI runner's file system.
- The developer moved the key to an environment variable and committed the corrected file. But the key was still in commit history, so the service account had to be rotated. The rotation broke two external services configured with the same key and took three hours to fix.

## The fix in the file
- Before (don't): the `headers.Authorization` value holds `Bearer sk-abc123...` inline.
- After: the config keeps the server `type` (`http`) and `url`, and the header refers to an environment variable, `Bearer ${WAREHOUSE_MCP_TOKEN}`.

## Takeaways
- Anything committed is in repository history. Overwriting the file in a later commit removes the key only from the current version. Treat any credential ever written inline in a committed file as compromised and rotate it. Correct pattern: value in an environment variable, config file refers to the variable.
- To stop the agent writing credentials into committed files, use two layers:
  1. A convention line in `CLAUDE.md`: never write credential values inline to `.mcp.json`. It signals the rule each session.
  2. A `PreToolUse` hook that inspects write and edit operations against `.mcp.json` for patterns that look like inline credentials and exits with code 2 to block them.
  The instruction communicates intent; the hook enforces it deterministically whatever the model decides. This is the instruction-versus-hook distinction from 03.05 and 03.06: a `CLAUDE.md` rule can be followed inconsistently as the file grows or context shifts, while a hook fires at every relevant tool call.
