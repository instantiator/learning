# 18. Glossary of Terms

Short, plain-language definitions of the terms used throughout this guide. Roughly ordered
from the fundamentals outwards.

## TypeScript and build tools

- **TypeScript** — JavaScript with type annotations. The types are stripped away when the
  code is compiled, so browsers/Node.js can run it.
- **Type checking / compile time** — the compiler (or your editor) verifying that your
  types are consistent, *before* the program runs.
- **Compiler (`tsc`)** — the program that converts TypeScript to JavaScript. NestJS's
  `nest build` uses it.
- **SWC** — a much faster alternative compiler, invoked with `nest start -b swc`. Skips
  type-checking to speed up development.
- **Decorator** — syntax beginning with `@` placed above a class/method/property (e.g.
  `@Controller('cats')`). NestJS reads it as metadata and wires things up accordingly.
- **tsconfig.json** — the settings file for the TypeScript compiler (target version,
  strictness, output folder, decorator support).
- **npm / npm scripts** — the package manager, and the short commands defined in
  `package.json` (`npm run start:dev`, etc.).
- **Monorepo** — one repository containing several related applications/packages (Nest CLI
  supports this mode).

## NestJS architecture

- **Module** — a grouping of related controllers and providers, described by `@Module`.
  The root module is `AppModule`.
- **Controller** — a class (marked `@Controller`) that maps HTTP routes to methods.
- **Provider / Service** — a class (marked `@Injectable`) that does the work. "Provider"
  is the generic term for anything NestJS can inject.
- **Dependency injection (DI)** — NestJS builds the objects you declare in constructors and
  hands them to you, instead of you calling `new` yourself.
- **DTO (data transfer object)** — a plain class that describes the *shape of data* moving
  in or out of an API (e.g. the body of a request).
- **Entity** — a class that maps to a database table (ORM) or document (ODM).
- **Guard** — runs before a handler and returns true/false; used for authentication and
  authorization (`CanActivate`).
- **Pipe** — transforms or validates incoming data before the handler receives it.
- **Interceptor** — wraps the handler; can transform outgoing data or add cross-cutting
  logic (caching, logging, serialization).
- **Exception filter** — catches thrown errors and converts them into responses.
- **Middleware** — runs before the handler for matching routes (body parsing, helmet...).
- **Reflector** — NestJS's helper for reading metadata attached by decorators (used by
  guards like `RolesGuard`).
- **Lifecycle hooks** — methods NestJS calls at defined moments: `onModuleInit`,
  `onApplicationBootstrap`, `onModuleDestroy`, `onApplicationShutdown`.
- **Adapter / platform** — the underlying HTTP library NestJS runs on: Express (default)
  or Fastify.
- **Execution context** — a wrapper giving guards/interceptors/etc. a uniform view of HTTP,
  WebSocket or microservice requests.

## Data

- **ORM (object-relational mapper)** — maps database tables to TypeScript classes
  (TypeORM, Prisma). You query via methods instead of raw SQL.
- **ODM (object-document mapper)** — the same idea for document databases (Mongoose +
  MongoDB).
- **Repository / Model** — the objects that wrap a table (TypeORM repository) or a
  collection (Mongoose model) and give you `find`, `save`, etc.
- **Migration** — a versioned, deliberate schema change (add a column, create a table).
  The safe production alternative to auto-synchronization.
- **Transaction** — a group of writes that succeed or fail together.
- **Seeding** — adding starter/development data to a database.
- **Serialization** — shaping the data *leaving* your API (hiding passwords, renaming
  fields).
- **Validation** — checking the data *entering* your API.

## Real-time

- **SSE (Server-Sent Events)** — one-way server-to-browser push over a plain HTTP
  connection, using the browser's `EventSource`.
- **WebSocket** — a persistent two-way connection between client and server.
- **Gateway** — the NestJS class that handles WebSocket connections.
- **Namespace** (socket.io) — a separate channel with its own connections; like a
  sub-server.
- **Room** (socket.io) — an arbitrary group of sockets within a namespace; messages can be
  targeted at a room.
- **Ack / acknowledgement** — the callback a client passes when emitting; the server's
  return value goes back through it.
- **Observable (rxjs)** — a stream of values over time; the type NestJS wants back from SSE
  and gateway handlers.

## Concurrency

- **Cron** — a schedule written as an expression (e.g. every day at 2am).
- **Queue** — a list of jobs awaiting processing by a worker; NestJS uses BullMQ + Redis.
- **Worker / processor** — the process (or class) that picks up and executes queued jobs.
- **Job** — a single unit of work in a queue, with data and options (retries, delay).
- **Redis** — an in-memory key-value store commonly used for queues, caching, rate-limit
  counters and WebSocket scaling.
- **TTL (time to live)** — how long something (a cache entry, a rate-limit window) lasts
  before expiring.

## Security

- **Authentication** — proving who you are.
- **Authorization** — deciding what you may do (roles, ownership).
- **JWT (JSON Web Token)** — a signed, stateless token containing claims; sent by clients
  as `Authorization: Bearer <token>`.
- **Hash / salt** — a one-way transformation of a password (bcrypt). "Salted" means random
  per-user data is mixed in so identical passwords differ.
- **CORS (Cross-Origin Resource Sharing)** — browser rules controlling whether a page on
  one origin may call another; configured on the server.
- **Origin** — scheme + host + port of a page (`https://app.example.com:443`).
- **CSRF (Cross-Site Request Forgery)** — an attack that abuses automatically-sent cookies
  to make a logged-in user's browser perform unwanted state-changing requests.
- **Helmet** — middleware that sets security headers (CSP, X-Frame-Options, HSTS...).
- **CSP (Content Security Policy)** — a header that says which sources a page may load
  scripts/styles from; blocks many XSS attacks.
- **Rate limiting** — capping requests per client per window; returns HTTP 429.
- **Clickjacking** — embedding your site in a hidden iframe to trick clicks.
- **XSS (cross-site scripting)** — injecting scripts into pages.
- **HTTP 401 vs 403** — 401: not authenticated. 403: authenticated but not allowed.

## API practice

- **OpenAPI / Swagger** — the standard format for describing an API; NestJS can generate
  docs and an interactive test UI from your code.
- **API versioning** — running several versions of routes side by side (`/v1/cats`,
  `/v2/cats`) so breaking changes don't break old clients.
- **Endpoint / route** — a URL + HTTP method your API exposes.
- **Preflight** — the `OPTIONS` request a browser sends before a cross-origin request to
  ask if it's allowed.
- **Bearer token** — a token sent in the `Authorization` header, treated as proof of
  identity.
- **Health check** — an endpoint (e.g. `GET /health`) that reports whether the app and its
  dependencies are alive.

## Lifecycle of an HTTP request in NestJS (recap)

```text
Middleware -> Guards -> Interceptors (before) -> Pipes -> handler
                                                    -> Interceptors (after) -> response
                                                    (errors) -> Exception filters
```

Guards decide *if*, pipes prepare the *input*, interceptors shape the *output*, filters
format *errors*.

That is the whole guide. If any chapter is still unclear, skim the matching NestJS
documentation section (docs.nestjs.com) — the code examples there match what you have seen
here.
