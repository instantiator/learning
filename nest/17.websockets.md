# 17. How to Set Up and Manage WebSockets

## What WebSockets give you

A WebSocket is a **persistent, two-way connection** between a client and your server. Once
open, either side can push messages at any time, with very low latency. Where SSE (chapter
09) is one-way server→client over HTTP, WebSockets are for genuinely interactive features:
chat, live collaboration, games, live dashboards, trading tickers.

NestJS supports two underlying WebSocket libraries:

- **socket.io** (`@nestjs/platform-socket.io`) — the default and recommended choice.
  Adds rooms, namespaces, reconnection and fallbacks on top of raw WebSockets.
- **ws** (`@nestjs/platform-ws`) — a thinner, faster raw implementation with fewer
  conveniences.

Everything below uses socket.io.

## Install

```bash
npm install @nestjs/websockets @nestjs/platform-socket.io
```

## The core concept: a gateway

A **gateway** is a class marked with `@WebSocketGateway()`. It is what a controller is to
HTTP — it receives messages from clients and sends messages back. Like any provider, it
can inject services and be listed in a module's `providers`.

```typescript
// events/events.gateway.ts
import { WebSocketGateway, SubscribeMessage, MessageBody, ConnectedSocket } from '@nestjs/websockets';
import { Socket } from 'socket.io';

@WebSocketGateway({ cors: { origin: 'http://localhost:3001' } })  // allow the frontend origin
export class EventsGateway {
  @SubscribeMessage('events')                       // client emits "events"
  handleEvent(
    @MessageBody() data: string,
    @ConnectedSocket() client: Socket,
  ): string {
    return data;                                    // sent back as an acknowledgement
  }
}
```

Register it:

```typescript
// events/events.module.ts
import { Module } from '@nestjs/common';
import { EventsGateway } from './events.gateway';

@Module({
  providers: [EventsGateway],   // without this, the gateway never starts
})
export class EventsModule {}
```

By default the gateway listens on the **same port as your HTTP server**. To use a
different port or a namespace, pass options to the decorator:

```typescript
@WebSocketGateway(81)                                  // separate port 81
@WebSocketGateway({ namespace: 'events' })             // isolated namespace
@WebSocketGateway({ transports: ['websocket'] })       // skip long-polling fallback
```

## Receiving and responding: the message handlers

| Decorator            | What it gives you                                            |
| -------------------- | ------------------------------------------------------------ |
| `@SubscribeMessage('name')` | Run this method when a client emits `name`.             |
| `@MessageBody()`     | The payload sent by the client. `@MessageBody('id')` gets just the `id` field. |
| `@ConnectedSocket()` | The socket instance for this client (emit directly, join rooms...). |
| `@Ack()`             | The acknowledgement callback, if the client passed one.       |

How responses reach the client:

```typescript
// 1. Return a value -> sent as an acknowledgement (client passes a callback)
handleEvent(@MessageBody() data: string): string {
  return `echo: ${data}`;
}

// 2. Return { event, data } -> emitted as a named event anyone can listen to
import { WsResponse } from '@nestjs/websockets';

handleEvent(@MessageBody() data: unknown): WsResponse<unknown> {
  return { event: 'events', data: `echo: ${data}` };
}

// 3. Return an Observable -> multiple emissions over time
import { from, map } from 'rxjs';

onEvent(): Observable<WsResponse<number>> {
  return from([1, 2, 3]).pipe(map((n) => ({ event: 'events', data: n })));
}
```

### Pushing from anywhere (not just message handlers)

Hold the server reference and send messages from services, scheduled jobs or queue
workers:

```typescript
import { WebSocketGateway, WebSocketServer } from '@nestjs/websockets';
import { Server } from 'socket.io';

@WebSocketGateway()
export class EventsGateway {
  @WebSocketServer()
  server: Server;                       // Nest assigns the server once ready

  broadcast(event: string, payload: unknown) {
    this.server.emit(event, payload);   // to every connected client
  }
}
```

Inject the gateway into any other service and call `broadcast(...)` — this is the pattern
for "tell everyone when an order ships".

## Rooms and namespaces (sending to a subset)

- **Rooms** — arbitrary groups of sockets within one gateway. Perfect for "a chat room"
  or "this user's own feed".

  ```typescript
  @SubscribeMessage('join')
  join(@MessageBody() room: string, @ConnectedSocket() client: Socket) {
    client.join(room);                       // socket enters the room
    this.server.to(room).emit('message', `welcome to ${room}`);
  }

  // from anywhere:
  this.server.to('chat-42').emit('message', 'hello room');
  ```

- **Namespaces** — separate top-level channels with their own lifecycle
  (`@WebSocketGateway({ namespace: 'admin' })`). Use them to split unrelated parts of the
  app (public vs admin sockets).

## Lifecycle hooks

| Interface              | Method to implement      | When it runs                                |
| ---------------------- | ------------------------ | ------------------------------------------- |
| `OnGatewayInit`        | `afterInit(server)`      | After the server starts; good place for setup. |
| `OnGatewayConnection`  | `handleConnection(client)`| A client connects.                          |
| `OnGatewayDisconnect`  | `handleDisconnect(client)`| A client disconnects.                       |

```typescript
import { OnGatewayConnection, OnGatewayDisconnect } from '@nestjs/websockets';
import { Socket } from 'socket.io';

@WebSocketGateway()
export class PresenceGateway implements OnGatewayConnection, OnGatewayDisconnect {
  private online = 0;

  handleConnection(client: Socket) {
    this.online++;
    this.broadcast('presence', { online: this.online });
  }

  handleDisconnect(client: Socket) {
    this.online--;
    this.broadcast('presence', { online: this.online });
  }
}
```

## Authentication on WebSockets

Guards, pipes, interceptors and exception filters all work on gateways. Socket.io is
slightly awkward because the client usually cannot set headers — the token is passed in
the **handshake query** or as an `auth` object during connection.

Client (socket.io client):

```javascript
const socket = io('http://localhost:3000', {
  auth: { token: '...' },        // sent during the handshake
});
```

Server — reject at connection time, or guard every message:

```typescript
@WebSocketGateway()
export class AuthGateway implements OnGatewayConnection {
  constructor(private readonly jwtService: JwtService) {}

  handleConnection(client: Socket) {
    const token = client.handshake.auth?.token;
    try {
      this.jwtService.verify(token);   // throws if invalid
    } catch {
      client.disconnect();             // refuse the connection
    }
  }
}
```

Note: the rate-limiting guard from chapter 16 needs a small subclass to work with
WebSockets (the docs show the exact snippet) — the key point is that HTTP-based defaults
count the socket's IP, which is what you want for brute-force protection.

## CORS for WebSockets

Browsers do not apply the same CORS preflight to WebSockets, but socket.io still lets you
whitelist origins. Set it on the gateway (as in the first example):

```typescript
@WebSocketGateway({
  cors: { origin: 'http://localhost:3001' },  // frontend origin
})
```

Leaving this open means any website can connect. Restrict it to your own frontend(s).

## Scaling beyond one process

State problem: rooms, and `this.server.emit`, live inside one process. With multiple app
instances, a client connected to instance A would not get messages emitted from instance
B. The fix is the **socket.io Redis adapter**, which relays events between all instances
through Redis:

```bash
npm install @socket.io/redis-adapter ioredis
```

```typescript
// main.ts
import { IoAdapter } from '@nestjs/platform-socket.io';
import { createAdapter } from '@socket.io/redis-adapter';
import { createClient } from 'ioredis';

const pubClient = createClient({ host: 'localhost', port: 6379 });
const subClient = pubClient.duplicate();

const app = await NestFactory.create(AppModule);
app.useWebSocketAdapter(
  new (class extends IoAdapter {
    createIOServer(port: number, options?: any) {
      const server = super.createIOServer(port, options);
      server.adapter(createAdapter(pubClient, subClient));
      return server;
    }
  })(app),
);
```

With the adapter, `emit`/`to(room)` reach every instance, and you can scale horizontally.

## Choosing between transports

| Feature            | socket.io                                   | ws                                  |
| ------------------ | ------------------------------------------- | ----------------------------------- |
| Rooms/namespaces   | Built in                                    | You build them yourself             |
| Reconnection       | Automatic + configurable                    | You handle it                       |
| Fallbacks          | HTTP long-polling fallback                  | WebSocket only                      |
| Typical use        | Chat, collaboration, real-time apps         | Lean high-throughput connections    |

Start with socket.io. Switch to `ws` only if you have a measured reason to (raw
throughput, minimal dependency).

## Summary of the mental model

- **Gateway = controller for sockets.** It owns the connection lifecycle and message
  routing; services do the real work.
- **`emit` sends**, **`@SubscribeMessage` receives**. Return values go back as
  acknowledgements; `{ event, data }` shapes go out as events.
- **Rooms** narrow who receives a broadcast. **Namespaces** separate concerns.
- **Auth** happens at the handshake (query token) and is re-checkable per message with
  guards.
- **Redis adapter** = multi-instance, production-ready scaling.
