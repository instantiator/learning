# 02. Setting Up a New Project

## What you need installed

- **Node.js** version 20 or newer (this is the JavaScript runtime that will execute your
  app). Check with `node --version`.
- **npm** (comes with Node.js). Check with `npm --version`.
- A text editor. Visual Studio Code is the most common choice and has excellent TypeScript
  support.

That is everything. There is no separate compiler to install — the Nest CLI manages that for
you.

## Installing the Nest CLI

The Nest CLI is a command-line tool that creates and manages NestJS projects. Install it
globally (once per machine):

```bash
npm install -g @nestjs/cli
```

You can verify it worked with:

```bash
nest --version
```

If you would rather not install it globally, prefix commands with `npx`, for example
`npx @nestjs/cli new project-name`.

## Creating a new project

```bash
nest new my-project
```

The CLI asks which package manager to use (npm / yarn / pnpm). It then:

1. Creates a `my-project/` folder.
2. Installs all dependencies.
3. Generates a working starter application.

Two useful flags:

```bash
nest new my-project --strict        # stricter TypeScript type checking
nest new my-project --package-manager npm
```

The `--strict` flag enables TypeScript's strict mode, which catches more bugs at compile
time. It is a good default.

## What you get

The generated project contains (ignoring configuration) a `src/` folder and test files:

```text
my-project/
├── src/
│   ├── main.ts                 # entry point; starts the application
│   ├── app.module.ts           # the root module
│   ├── app.controller.ts       # a sample controller (Hello World)
│   ├── app.controller.spec.ts  # unit tests for the controller
│   └── app.service.ts          # a sample service
├── test/
│   └── app.e2e-spec.ts         # end-to-end tests
├── package.json                # dependencies and npm scripts
├── tsconfig.json               # TypeScript compiler settings
├── nest-cli.json               # Nest CLI settings
├── eslint.config.mjs           # linting rules
├── .prettierrc                 # formatting rules
└── .gitignore
```

### The entry point: `src/main.ts`

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

`main.ts` does four things:

- `NestFactory.create(AppModule)` builds the whole application from the root module.
- Configuration calls live here (CORS, global pipes, helmet, versioning, etc.).
- `app.listen(port)` starts the HTTP server.
- The returned object lets you enable all the global features covered later in this guide.

### The root module: `src/app.module.ts`

```typescript
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
  imports: [],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
```

As your app grows, `imports` fills with your feature modules.

## Running the application

The `package.json` of a new project defines the standard npm scripts:

```bash
npm run start        # build and start once
npm run start:dev    # development: rebuild and restart on every file change
npm run start:prod   # run the previously built version from dist/
npm run build        # compile TypeScript into JavaScript in dist/
npm run lint         # check code style
npm run format       # auto-format with prettier
npm run test         # unit tests
npm run test:e2e     # end-to-end tests
```

The command you will use most while developing is `npm run start:dev`. It watches your
files, recompiles and restarts automatically.

Open `http://localhost:3000` in a browser and you should see `Hello World!`.

## How the TypeScript build works (plain explanation)

Your code in `src/` is TypeScript. Before it can run, it must be converted to plain
JavaScript. NestJS does this with a tool called the **compiler**:

- **Default compiler: `tsc`.** The official TypeScript compiler. It type-checks your code
  and emits JavaScript into `dist/`. When you run `nest build` or `nest start`, `tsc` does
  the work.
- **Faster alternative: SWC.** A much faster compiler written in Rust. To use it, add
  `-b swc`:

  ```bash
  npm run start:dev -- -b swc
  ```

  SWC skips full type-checking (your editor still checks types). For big projects it makes
  the dev loop dramatically faster.

The key settings live in `tsconfig.json`. A new project is already correctly configured for
NestJS; you rarely need to touch it. You can think of it as the "settings file" that tells
the compiler how to behave (which JavaScript version to target, where to put the output,
whether decorators are enabled, and so on).

## The project layout convention

NestJS strongly encourages one folder per feature module, and the CLI supports it through
generator commands:

```bash
nest g module cats        # creates cats/cats.module.ts
nest g controller cats    # creates cats/cats.controller.ts (+ spec)
nest g service cats       # creates cats/cats.service.ts (+ spec)
nest g resource products  # creates a full CRUD module with routes, DTOs, and tests
```

`nest g resource` is the fastest way to bootstrap a feature: it asks for the transport
(REST / GraphQL / WebSocket / microservice) and generates everything.

## Express or Fastify?

NestJS can run on two underlying HTTP libraries:

- **Express** — the default. Battle-tested, enormous ecosystem, many plugins. Most projects
  should just use it.
- **Fastify** — faster and more lightweight. Use it if you need maximum throughput.

Switching to Fastify only changes the entry point:

```typescript
import { NestFactory } from '@nestjs/core';
import { FastifyAdapter, NestFastifyApplication } from '@nestjs/platform-fastify';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create<NestFastifyApplication>(
    AppModule,
    new FastifyAdapter(),
  );
  await app.listen(3000);
}
bootstrap();
```

Some security packages have Express and Fastify variants (see the Helmet and CSRF chapters).
Every example in this guide uses Express, which is the default.

## Setting up the usual starting point in `main.ts`

A realistic `main.ts` after a few of the steps in this guide:

```typescript
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import helmet from 'helmet';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.use(helmet());                       // security headers
  app.enableCors({ origin: 'http://localhost:3001' }); // allow the frontend
  app.setGlobalPrefix('api');              // all routes under /api/...
  app.useGlobalPipes(
    new ValidationPipe({ whitelist: true, transform: true }),
  );                                        // validate + shape incoming data
  app.enableShutdownHooks();               // clean up on Ctrl-C / signals

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

Each line above is explained in the chapters that follow. The pattern to remember: **global
configuration lives in `main.ts`, and the rest of the structure lives in modules.**
