# 09. How Server-Sent Events (SSE) Are Supported

## What SSE is

Server-Sent Events is a way for the **server to push updates to a browser over a plain
HTTP connection**, one way only. The browser opens a special request and the server keeps
the connection open, sending a stream of text events whenever something happens.

Where it fits compared to other real-time options:

- **SSE**: server → client, over normal HTTP, automatic reconnection built in, very simple.
- **WebSockets**: bidirectional (both directions), needs a separate protocol/handshake.
- **Polling**: client repeatedly asks; wasteful compared to a persistent stream.

Use SSE when the data flows one way (notifications, live scores, progress updates, stock
tickers) and your clients are browsers. It is simpler than WebSockets and survives
proxies/load balancers better.

## How the protocol works

The server responds with the `Content-Type: text/event-stream` and keeps the socket open.
Messages look like:

```text
data: {"temperature": 21.5}

```

Each message is one or more `field: value` lines followed by a blank line. Supported
fields:

| Field     | Purpose                                            |
| --------- | -------------------------------------------------- |
| `data`    | The payload (string or JSON).                      |
| `id`      | An event id; used by the browser for reconnection. |
| `event`   | A custom event name the client listens for.        |
| `retry`   | Milliseconds the browser waits before reconnecting.|

On the browser side you use the built-in `EventSource` API — no library needed.

## Defining an SSE endpoint in NestJS

Install nothing extra. Import `@Sse()` from `@nestjs/common`, `Observable` from `rxjs`
(already a dependency of NestJS), and return a stream of `MessageEvent` objects.

```typescript
// weather/weather.controller.ts
import { Controller, Sse } from '@nestjs/common';
import { Observable, interval, map } from 'rxjs';

@Controller('weather')
export class WeatherController {
  @Sse('live')
  live(): Observable<MessageEvent> {
    return interval(1000).pipe(
      map((tick) => ({ data: { temp: 20 + Math.round(Math.random() * 5) } })),
    );
  }
}
```

Rules:

- The method **must return an `Observable`** (from rxjs).
- Each emission becomes one SSE message. `{ data: ... }` is the `data` field.
- The connection stays open until the Observable completes or the client disconnects.

You can emit the other fields too:

```typescript
map((tick) => ({
  data: { temp: 21 },
  id: String(tick),        // lets the browser resume from the last id
  event: 'temperature',    // client listens for "temperature" instead of "message"
  retry: 5000,
}))
```

## A client example

```javascript
const events = new EventSource('/weather/live');

// default event, when no "event" field is sent
events.onmessage = ({ data }) => {
  console.log('temperature update:', JSON.parse(data));
};

// custom event name
events.addEventListener('temperature', ({ data }) => {
  console.log('custom event:', data);
});
```

Calling `events.close()` ends the connection.

## Cleanup when a client disconnects

When the client disconnects, NestJS unsubscribes from your Observable automatically —
timers and intervals from `interval()` stop by themselves. For your own cleanup (close
database cursors, stop background listeners), use the `finalize` operator:

```typescript
import { finalize } from 'rxjs';

return interval(1000).pipe(
  map((tick) => ({ data: { temp: 21 } })),
  finalize(() => console.log('client left, cleaning up')),
);
```

## Going from a real event source (not just a timer)

Timers are only for illustration. In practice your SSE stream usually bridges an internal
event emitter or the database:

```typescript
import { Subject } from 'rxjs';

@Injectable()
export class NotificationsService {
  private readonly stream = new Subject<MessageEvent>();

  emit(event: MessageEvent) {
    this.stream.next(event);
  }

  watch(): Observable<MessageEvent> {
    return this.stream.asObservable();
  }
}
```

Your SSE controller returns `this.notificationsService.watch()`, and anywhere in the app
(including inside a job worker, see chapter 08) you call
`notificationsService.emit({ data: {...} })` to push a message to all connected clients.
Wrap the subject in a `filter`/`map` if clients should only receive a subset.

## Working with the rest of NestJS

- SSE routes live in normal controllers, so **guards, pipes and interceptors work** —
  you can protect the stream with your auth guard and reject unauthenticated clients.
- Compression middleware (gzip) is generally not compatible with SSE streams — if you
  enable compression globally, be prepared to disable it for SSE routes.
- CORS still applies if the page and the API are on different origins (see chapter 13);
  the browser's `EventSource` uses normal CORS rules.

## When to choose SSE vs WebSockets

| Need                                   | Use           |
| -------------------------------------- | ------------- |
| Server pushes data to browsers         | SSE           |
| Browser sends messages back frequently | WebSockets    |
| Bidirectional, low latency (chat, games)| WebSockets   |
| Simple, resilient, behind proxies      | SSE           |
