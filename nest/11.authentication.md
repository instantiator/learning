# 11. How to Set Up Authentication and Authorization

First, two words that are often used as if they were the same thing:

- **Authentication** — *who are you?* Proving identity (log in with username/password,
  get a token, send the token on each request).
- **Authorization** — *what may you do?* Deciding whether the identified user may access
  this resource (admin only, owner only). See the next chapter.

This chapter is about authentication. The common design it describes is **JWT-based
authentication**: the server signs a small "token" when you log in, and every subsequent
request proves who you are by carrying that token.

## What a JWT is (plainly)

A JWT (JSON Web Token) is a short string in three parts, each separated by a dot:

```text
header.payload.signature
```

- **header**: says which signing algorithm was used.
- **payload**: your claims, e.g. `{ "sub": 42, "username": "john", "exp": 1700000000 }`.
- **signature**: a cryptographic checksum. It is what makes the token tamper-proof — a
  server holding the same secret can verify the token was really issued by it and has not
  been edited.

Tokens are **signed, not encrypted** — anyone can read the payload, so never put secrets
in there. Their value is that the server does not need to store session state: it can
verify the signature statelessly.

The client sends the token on each request as a **bearer token**:

```text
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

## The full flow

```text
Client                      Server
  |  POST /auth/login         |
  |  { username, password }   |
  |-------------------------->|
  |                           | verify password (bcrypt compare)
  |                           | sign a JWT with @nestjs/jwt
  |  200 { access_token }     |
  |<--------------------------|
  |  GET /profile             |
  |  Authorization: Bearer JWT|
  |-------------------------->|
  |                           | AuthGuard verifies the token signature
  |                           | reads userId from the payload
  |  200 { ...user... }       |
  |<--------------------------|
```

## Step 1: install the pieces

```bash
npm install @nestjs/jwt @nestjs/passport passport passport-jwt bcrypt
```

- `@nestjs/jwt` — generates and verifies JWTs, wired into NestJS.
- `@nestjs/passport` + `passport` + `passport-jwt` — the standard strategy framework
  (optional but very common; you can also write your own guard, as below).
- `bcrypt` — hashes passwords. Never store plaintext passwords.

> Passwords 101: store `bcrypt.hash(password, saltRounds)` at signup; at login compare
> with `bcrypt.compare(input, storedHash)`. Hashing is one-way — even if your database
> leaks, the passwords do not.

## Step 2: configure the JWT module

In your `AuthModule`, register `JwtModule`. The `secret` must come from configuration
(environment variable), never from source code.

```typescript
// auth/auth.module.ts
import { Module } from '@nestjs/common';
import { JwtModule } from '@nestjs/jwt';
import { ConfigModule, ConfigService } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule,
    JwtModule.registerAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        secret: config.get('JWT_SECRET'),                 // keep it secret!
        signOptions: { expiresIn: config.get('JWT_EXPIRES_IN', '15m') },
      }),
    }),
  ],
})
export class AuthModule {}
```

## Step 3: the login endpoint (sign a token)

```typescript
// auth/auth.service.ts
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { UsersService } from '../users/users.service';
import * as bcrypt from 'bcrypt';

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
  ) {}

  async signIn(username: string, password: string) {
    const user = await this.usersService.findByUsername(username);
    if (!user || !(await bcrypt.compare(password, user.passwordHash))) {
      throw new UnauthorizedException('Invalid credentials');
    }
    const payload = { sub: user.id, username: user.username };
    return { access_token: await this.jwtService.signAsync(payload) };
  }
}
```

```typescript
// auth/auth.controller.ts
import { Body, Controller, HttpCode, HttpStatus, Post } from '@nestjs/common';
import { AuthService } from './auth.service';
import { SignInDto } from './dto/sign-in.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @HttpCode(HttpStatus.OK)
  @Post('login')
  signIn(@Body() dto: SignInDto) {
    return this.authService.signIn(dto.username, dto.password);
  }
}
```

## Step 4: a guard that checks the token

A **guard** runs before the route handler and decides whether to let the request through.
This guard verifies the JWT:

```typescript
// auth/auth.guard.ts
import {
  CanActivate,
  ExecutionContext,
  Injectable,
  UnauthorizedException,
} from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { Request } from 'express';

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private readonly jwtService: JwtService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest<Request>();
    const token = this.extractToken(request);
    if (!token) throw new UnauthorizedException();

    try {
      const payload = await this.jwtService.verifyAsync(token); // checks signature + expiry
      request['user'] = payload;                                // available to handlers
      return true;
    } catch {
      throw new UnauthorizedException();                        // invalid or expired
    }
  }

  private extractToken(request: Request): string | undefined {
    const [type, token] = request.headers.authorization?.split(' ') ?? [];
    return type === 'Bearer' ? token : undefined;
  }
}
```

## Step 5: protect a route

```typescript
// users/users.controller.ts
import { Controller, Get, Request, UseGuards } from '@nestjs/common';
import { AuthGuard } from '../auth/auth.guard';

@Controller('users')
export class UsersController {
  @UseGuards(AuthGuard)
  @Get('profile')
  profile(@Request() req) {
    return req.user;   // the payload we attached in the guard
  }
}
```

Inside the handler, `req.user` carries the authenticated identity (`sub`, `username`).
Authorization rules in the next chapter build on this.

## Making it global (protect everything by default)

Most endpoints should require a token. Register the guard once and declare exceptions
explicitly:

```typescript
// anywhere, e.g. auth/auth.module.ts
providers: [
  {
    provide: APP_GUARD,       // registers the guard for every route
    useClass: AuthGuard,
  },
],
```

Then create a `@Public()` decorator for the few routes that must stay open (login,
registration, health):

```typescript
// common/public.decorator.ts
import { SetMetadata } from '@nestjs/common';

export const IS_PUBLIC_KEY = 'isPublic';
export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);
```

```typescript
@Public()
@Get('health')
health() {
  return { status: 'ok' };
}
```

And make the guard respect it, using the `Reflector`:

```typescript
constructor(
  private readonly jwtService: JwtService,
  private readonly reflector: Reflector,
) {}

async canActivate(context: ExecutionContext): Promise<boolean> {
  const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
    context.getHandler(),
    context.getClass(),
  ]);
  if (isPublic) return true;   // skip auth for @Public() routes

  // ... the JWT verification from step 4 ...
}
```

## The Passport alternative

The flow above is written by hand to make every step visible. Many production apps instead
use **Passport strategies** via `@nestjs/passport`, which packages each auth method (jwt,
google, github, local...) into a reusable strategy:

```typescript
// auth/jwt.strategy.ts
import { Injectable } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      secretOrKey: process.env.JWT_SECRET,
    });
  }

  async validate(payload: any) {
    return { userId: payload.sub, username: payload.username };
  }
}
```

Then a built-in `AuthGuard('jwt')` protects routes:

```typescript
@UseGuards(AuthGuard('jwt'))
@Get('profile')
profile(@Request() req) {
  return req.user;
}
```

Use whichever style you find clearer. The hand-rolled version teaches the concepts; the
Passport version plugs into dozens of existing strategies (OAuth, social login, etc.).

## Sessions vs tokens (choosing an approach)

| Aspect             | JWT / bearer token                     | Session (cookie)                         |
| ------------------ | -------------------------------------- | ---------------------------------------- |
| Server state       | Stateless (verify signature)           | Server must store the session            |
| Scaling            | Easy (any instance can verify)         | Needs shared session store (e.g. Redis)  |
| Clients            | Mobile, SPA, APIs                      | Classic web apps, server-rendered pages  |
| Revocation         | Hard (wait for expiry, or blocklists)  | Easy (delete the session)                |
| CSRF risk          | Low (token not sent automatically)     | Higher — see chapter 15 (CSRF)           |

For a JSON API consumed by a frontend or mobile app, JWT in an `Authorization` header is
the standard default. For server-rendered websites, cookie sessions are more natural.

## Security checklist

- `JWT_SECRET`: long, random, from environment/config — never hard-coded.
- Short token lifetime (`expiresIn`), with a **refresh token** if you need longer-lived
  sessions (a second long-lived token that can mint new access tokens).
- Store passwords only as **bcrypt hashes**.
- Always use HTTPS in production.
- Return `401` for "not authenticated"; return `403` when authenticated but not allowed
  (next chapter).
